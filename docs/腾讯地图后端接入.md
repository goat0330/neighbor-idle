# 腾讯地图后端接入

## 目标

微信小程序生产环境不再直接携带腾讯地图 WebService Key。地图底图仍使用微信原生 `<Map>`，需要地址解析或 POI 查询时，Taro 服务调用 CloudBase 云函数 `tencentMap`，由云函数读取 `TENCENT_MAP_KEY` 并访问腾讯位置服务。

```text
MapPicker / locationService
        ↓  cloud.callFunction
cloudfunctions/tencentMap
        ↓  TENCENT_MAP_KEY（云函数环境变量）
https://apis.map.qq.com
```

## 云函数契约

统一返回 `{ code: 0, data }` 或 `{ code: -1, msg }`。

| action | 输入 | 返回 |
|---|---|---|
| `reverseGeocode` | `latitude`, `longitude` | 地址、省/市/区、街道、最近 POI、小区推荐名 |
| `searchPOI` | `latitude`, `longitude`, 可选 `keyword`、`radius`、`page` | `{ list, total }`，列表含 POI 坐标和距离 |
| `searchKeyword` | `keyword`，可选 `latitude`、`longitude` | 地址候选列表 |
| `suggestAddress` | `keyword`，可选 `latitude`、`longitude` | 输入提示候选列表 |

云函数会校验坐标、关键词、搜索半径和页码，并限制周边搜索最多 10 km、每页 20 条，避免客户端任意放大调用范围。

## 配置与部署

1. 在腾讯位置服务控制台创建 WebService Key，将授权来源绑定正式小程序 AppID，并按实际使用接口和配额限制权限。
2. 在 CloudBase 控制台为 `tencentMap` 云函数设置环境变量：

   ```text
   TENCENT_MAP_KEY=<真实 Key>
   ```

   真实 Key 只放云函数环境变量，不写入仓库、`.env.local`、`project.private.config.json` 或前端配置。

3. 用微信开发者工具打开 `apps/workbuddy-app`，右键 `cloudfunctions/tencentMap`，选择“上传并部署：云端安装依赖”。
4. Taro 小程序只配置 `TARO_APP_CLOUD_ENV=<CloudBase 环境 ID>`，重新构建并导入 `apps/codex-taro-app/dist`。
5. 在开发者工具的云函数日志中确认 `tencentMap` 已部署；再真机验证定位、逆地理编码、周边小区搜索和地图拖拽选点。

## 本地模式

未配置 `TARO_APP_CLOUD_ENV` 时，H5 预览仍可使用 `TARO_APP_TENCENT_MAP_KEY` 直连腾讯接口，便于本地视觉调试。微信小程序接入 CloudBase 后会优先走云函数；生产构建不应依赖前端 Key。

## 当前不能代替人工完成的上线动作

仓库中没有真实 Key、正式 CloudBase 环境和开发者工具登录态，因此本次代码验证不能证明腾讯线上接口或云函数已经部署成功。部署后仍需使用真实环境做一次真机 smoke，并完成腾讯 Key 配额、微信隐私指引和小程序提审配置。
