# 两个小程序版本对比

## 定位

| 版本 | 技术栈 | 当前职责 | 适合谁 |
| --- | --- | --- | --- |
| WorkBuddy | 组件化微信小程序 + CloudBase 云函数 | 业务闭环、组件复用和后台能力基线 | 先验证真实云开发流程、审核和数据权限 |
| Codex | React + TypeScript + Vite + Taro | 组件化界面、交互体验和多端演进 | 继续做 UI、动效、接口抽象和后续多端扩展 |

## 功能边界

WorkBuddy 版本已有组件化页面、云函数、登录/小区认证、闲置发布、求购、留言、收藏和管理审核分包，作为真实数据链路和组件拆分方式的参考实现。当前共享路径与 ZIP 中未发现独立 `components` 文件夹或自定义组件注册，需以 WorkBuddy 最新工作副本继续核对。Codex Taro 版本迁移核心用户流程和设计系统，数据层通过 repository/service 接口隔离，后续可以接入 WorkBuddy 的云函数，而不把云调用散落在 React 组件里。

## 迁移顺序

1. 先统一商品、用户、小区、会话、求购和信用评价的数据契约。
2. 把 `我想要 → 聊天议价 → 约定自提 → 确认成交 → 互评` 作为主链路。
3. 接入定位授权和距离计算，前端只显示“同小区 / 距你 800m”等模糊安全信息。
4. 接入内容安全审核、举报拉黑和订阅消息授权。
5. 以真实微信开发者工具编译结果为准合并两个版本的可用能力。
