# 数据模型与接口

## 核心集合

| 集合 | 关键字段 | 访问原则 |
|---|---|---|
| `users` | openid、昵称、communityId、building、verificationStatus、creditTags、wechatId | 微信号永不随公开资料返回 |
| `items` | owner、标题、描述、图片、价格、分类、经纬度、模糊地址、状态、审核状态 | 公开接口只返回模糊位置 |
| `wants` | owner、标题、预算、分类、描述、过期时间 | 仅展示有效且审核通过记录 |
| `conversations` | itemId、buyerOpenid、sellerOpenid、lastMessage、lastMessageAt、status | 仅参与者可读 |
| `messages` | conversationId、senderOpenid、recipientOpenid、type、content、read、createdAt | 仅参与者可读写，服务端校验 |
| `contact_requests` | conversationId、itemId、buyerOpenid、sellerOpenid、reason、status、时间 | 仅双方可读，只有卖家可批准 |
| `transactions` | itemId、buyer、seller、自提时间、公共点、状态 | 不保存私聊后的付款凭证 |
| `reviews` | transactionId、from、to、标签、文本 | 一单双方各评价一次 |
| `reports` | reporter、targetType、targetId、reason、evidence、status | 仅举报人和管理员可读 |

## 联系方式状态机

`pending → approved | rejected`，双方任一方可将有效授权变更为 `revoked`。服务端仅在 `approved` 且请求者属于交易双方时返回微信号。任何列表、搜索、消息摘要接口都不返回微信号。

后端实现位于 `apps/workbuddy-app/cloudfunctions/user`、`conversation` 和 `contact`。Taro 设置 `TARO_APP_CLOUD_ENV` 后会直接调用这些云函数；未设置环境时才启用不持久化微信号的演示降级。

## 云函数接口

- `user`: `me`、`updateProfile`、`setWechat`、`bindCommunity`、`publicProfile`
- `conversation`: `open`、`detail`、`list`、`messages`、`send`、`markRead`、`unread`
- `contact`: `get`、`request`、`respond`、`revoke`、`listPending`

所有接口统一返回 `{ code: 0, data }` 或 `{ code: -1, msg }`。前端不传 openid；买卖角色由会话记录和云端微信上下文共同决定。

## 必建索引

- `conversations`: `buyerOpenid + lastMessageAt(desc)`、`sellerOpenid + lastMessageAt(desc)`、`itemId + buyerOpenid + sellerOpenid`
- `messages`: `conversationId + createdAt(desc)`、`recipientOpenid + read`
- `contact_requests`: `conversationId + createdAt(desc)`、`sellerOpenid + status + createdAt(desc)`
- `users`: `openid` 唯一业务索引

## 消息提醒

站内未读数始终保留；订阅消息只在用户主动授权后、针对一次具体事件使用，例如“收到新留言”“卖家同意交换联系方式”“自提时间临近”。授权拒绝不影响站内消息，也不使用营销通知冒充交易提醒。
