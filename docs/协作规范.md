# 协作规范

## 分支与 worktree

正式交付只保留当前 `community-visual` worktree，产品源代码位于 `apps/codex-taro-app`，同一 worktree 内的 `apps/workbuddy-app` 只承载 CloudBase 云函数和原生参考基线。

```text
D:\研究生作业\小程序开发\worktrees\community-visual
```

前端修改只进入 `apps/codex-taro-app`；后端云函数由后端 worker 维护并在同一 worktree 对齐。WorkBuddy 和 Taro 的组件运行时不同，不直接复制组件实现；公共接口契约先更新文档，再由负责该模块的人修改。

## 提交与合并

- 提交格式：`feat(scope): ...`、`fix(scope): ...`、`docs(scope): ...`、`chore(scope): ...`。
- 每个 PR 只解决一个主题，标题写清楚版本和模块。
- 合并前至少通过对应版本的静态检查；涉及页面时补充真机/开发者工具截图。
- 不提交 `node_modules`、构建产物、`project.private.config.json`、密钥、真实用户数据。

## Figma 决策流程

Figma 是界面和交互的决策来源。拿到 Figma 文件链接或节点后，先记录页面、组件、变量和动效决策，再落到 `docs/figma/` 与 `src/design/`。没有 Figma 链接时，以当前已确认的 P3/P4 参考图建立临时设计契约，并在后续 Figma 文件接入后校准，不直接凭感觉覆盖设计。
